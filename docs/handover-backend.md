# Бэкенд: состояние и как его воспроизвести

Документ для того, кто берёт работу дальше. Отвечает на три вопроса: что
работает, как это запустить и на чём здесь спотыкаются.

## Что работает

Конвейер собран целиком и проверен на живой модели, а не на заглушке:

```
ссылка на PR
   → ingest          SubmissionBundle: диффы, карта репозитория, история ревизий
   → ai/content      тексты артефактов: excerpt | дозагрузка по content_ref | дифф
   → ai/gate         формальные проверки рубрики, без единого токена
   → ai/review       вердикты по критериям с цитатами; балл считает агрегатор
   → ai/detection    четыре сигнала ГенИИ, вывод рекомендательный
```

Рядом — Rubric Compiler: условие задания → черновик рубрики → подтверждение
методистом → рубрика вступает в силу. И распределение: профиль работы от
модели → венгерский солвер → план, в котором каждое назначение объяснено
вкладом каждого слагаемого.

Замеры на живой модели (`deepseek-v4-flash`, записанные сдачи из
`backend/scripts/fixtures/`):

| Работа | Балл | Цитаты подтверждены | Стоимость |
|---|---|---|---|
| Go, код | 9/10 | 9 из 10 | 0.43 ₽ |
| System design, текст | 4.5/6 | 9 из 9 | 0.69 ₽ |
| Компиляция рубрики (`gpt-5.6-luna-pro`) | — | 100% критериев | ~2 ₽ один раз на задание |

368 тестов, `uv run pytest` из `backend/`.

## Запуск

```bash
cd backend
uv sync --group dev
uv run pytest                                          # тесты, ключи не нужны
uv run uvicorn avito_reviewer.app.main:app --reload     # http://localhost:8000/docs

docker compose up --build                               # из корня репозитория
```

Без ключей поднимается провайдер `fake`: конвейер проходится целиком, но
заглушке нечего ответить, и черновик приходит с пометкой «оценить вручную».
Готовый черновик без ключа показывает демо:

```bash
uv run python scripts/demo.py review     # записанная сдача
uv run python scripts/demo.py detect
uv run python scripts/demo.py review --repo путь/к/каталогу   # своя работа
uv run python scripts/demo.py review --link https://github.com/owner/repo/pull/1
```

## Конфигурация

Переменные окружения, `pydantic-settings`, см. `backend/src/avito_reviewer/config.py`.

```bash
INGEST_GITHUB__TOKEN=ghp_...              # без него 60 запросов в час на всё
AI_LLM__PROVIDER=external                 # fake | local | external
AI_LLM__BASE_URL=https://api.aitunnel.ru/v1
AI_LLM__MODEL=deepseek-v4-flash
AI_LLM__API_KEY=...
AI_LLM__TASK_MODELS={"compile": "gpt-5.6-luna-pro"}   # матрица роутинга, §8.3
AI_LLM__FORCE_LOCAL=false                 # аварийный тумблер: наружу не ходим
AI_RUBRICS_DIR=rubrics
AI_REVIEWERS_DIR=reviewers
INGEST_AUTHOR_SALT=...                    # ею же ищется соавторство при распределении
```

**Почему матрица, а не одна модель.** Задачи разные по цене ошибки. Ревью идёт
потоком — там решает стоимость. Rubric Compiler считается один раз на задание,
его результат подтверждает человек, а ошибка тиражируется на весь поток — там
решает устойчивость. Замер на одном и том же условии: `deepseek-v4-flash`
дважды дал разный результат и один раз вернул ноль критериев, `gpt-5.6-luna-pro`
— шесть критериев со стопроцентным подтверждением цитатами.

## Ручки

| Ручка | Что делает |
|---|---|
| `GET /health`, `GET /init` | живость и состав бутстрапа |
| `POST /ingest` | ссылка → `SubmissionBundle` |
| `POST /review` | сдача + рубрика → черновик с проверенными цитатами; `with_detection` добавляет отчёт детектора тем же прогоном |
| `POST /detect` | сдача → рекомендательный отчёт о признаках ГенИИ |
| `GET /rubrics`, `GET /rubrics/{id}` | каталог рубрик |
| `POST /rubrics/compile` | условие → черновик рубрики (ничего не сохраняет) |
| `POST /rubrics` | подтверждение методистом: рубрика вступает в силу |
| `POST /work-profile` | сдача → профиль работы и готовая к распределению единица |
| `POST /distribute` | работы + ревьюеры → план с объяснением каждого назначения |
| `GET /cost` | журнал шлюза: вызовы, токены, рубли |

`/review` и `/detect` сами тянут сдачу по ссылке и отдают `bundle` вместе с
результатом: базы ещё нет, поэтому каждый прогон — свежий ingest. Ревью с
детектором просят одним запросом (`with_detection`): раздельные вызовы не только
тратят лимит GitHub дважды, но и расходятся по ревизиям, если студент пушнул
между ними, — тогда спаны детектора описывают не ту работу, что цитаты черновика.

## Решения, которые не надо пересматривать наугад

**Балл считает код, а не модель.** Модель отвечает по одному критерию и обязана
приложить цитату; цитата сверяется с текстом файла программно; сумму считает
`review/aggregate.py`. Это отсекает основную массу галлюцинаций.

**Единственный выход к моделям — `PrivacyGateway`.** Скраб ПДн, проверка
остаточного риска, маршрут, аудит. Правило проверяется тестом
`test_llm_calls_leave_only_through_the_gateway`, а не обещанием: SDK моделей вне
`ai/llm` запрещены, сетевые вызовы разрешены ещё и в `ingest` — доступ к
источнику сдачи это его работа.

**Неполнота видна на всём пути.** Полного текста файла может не быть: ingest
инлайнит `excerpt` только в пределах бюджета. Такие файлы помечены `partial`, и
это тянется в промпт, в цитаты, в черновик и в ограничения детектора. Вердикт
«в работе нет обработки ошибок», сделанный по одному ханку, — некорректный
вердикт, и система это знает.

**Рубрика проверяется кодом перед принятием.** Недостижимый порог зачёта,
минимум выше максимума критерия, повторяющиеся идентификаторы — всё это ломает
подсчёт не на одной работе, а на каждой до конца курса.

**Распределение не ходит к модели и воспроизводимо.** Профиль работы строит
модель один раз, дальше решает арифметика: стоимости целочисленные, ничьи
разрешаются по индексу, времени генерации в плане нет. Координатор, увидевший в
10:00 и в 10:05 разные распределения одного пула, перестанет пользоваться
системой, а объяснить студенту «почему тебя проверяет он» вероятностным ответом
нельзя. Раунд — одна работа на ревьюера, между раундами нагрузка
пересчитывается: одна большая матрица посчитала бы загрузку по входящему
состоянию и дала бы оптимум не той функции.

**Терм без данных отключается, а не обнуляется.** Обнулённое слагаемое в отчёте
неотличимо от посчитанного и давшего ноль. Правило: отсутствие данных отключает
(нет профиля — не знаем сложности), осмысленное отсутствие даёт ноль (нет
прошлого ревьюера — работа первая). Доступность решается на прогон, а не на
пару: венгерский сравнивает всю матрицу, и работы с разным набором слагаемых
оказались бы на разных шкалах.

## Грабли, на которые уже наступали

**Рассуждающие модели тратят на `reasoning` тот же бюджет, что и на ответ.** При
`max_tokens=3000` JSON обрывался на середине, и батч критериев терялся. Обрыв
виден по `finish_reason`, лечится повтором с удвоенным бюджетом (потолок —
четыре исходных), а не ремонтным запросом: модель не ошиблась, ей не хватило
места. Пустой ответ — того же происхождения.

**Тройные кавычки внутри значения JSON.** Работа по системному дизайну состоит
из блоков ```` ```mermaid ````, модель цитирует диаграмму, и поиск ограды по
всему тексту вырезал содержимое диаграммы вместо ответа. Ограда снимается,
только если обрамляет ответ целиком.

**Ответ шлюза неизвестной формы.** `"usage": null` встречается; разбор «в лоб»
давал AttributeError, который конвейер не ловит, и один странный ответ
превращался в пятисотку на весь запрос. Разбор не верит форме ответа и
превращает неожиданность в `LLMError`, который переживается потерей одного батча.

**Лимит GitHub без токена — 60 запросов в час**, а один `/review` тратит
несколько. Штатная политика githubkit пережидает лимит `sleep`-ом до часа;
отключена, лимит всплывает сразу как 502.

**Тестовые двойники должны совпадать с настоящими провайдерами.** Дважды ошибка
пряталась именно на этом расхождении: `fake_gateway` ставит провайдера и
внешним, и локальным, а `gateway_from_config` — нет; `FakeProvider` отвечал
своей моделью вместо запрошенной. Оба случая закрыты тестами.

**`~/.zshrc` не читается неинтерактивной оболочкой.** Если ключ живёт там,
скриптам нужен явный `source ~/.zshrc`.

## Чего нет

- Format Gate знает только git-канал: шрифт и число страниц живут в Google Docs.
  Нереализованная проверка не исчезает — уходит ревьюеру как непроверенная.
- Перплексия ждёт локального сервинга с logprobs (`AI_LLM__PROVIDER=local`).
- Пороги детектора не калиброваны: нужны вердикты ревьюеров, схема под это готова.
- NER на локальной модели поверх регулярок скраба: `TaskKind.NER` уже заперт в
  локальный маршрут, самой модели нет. Имя без отчества и без маркера авторства
  остаётся риском, и `residual_risk` о нём сообщает.
- Ни базы, ни очереди: каждый прогон — свежий ingest, рубрики лежат файлами.
- Из §9 не построены профили ревьюера и студента: они определены как пересчёт
  по истории ревью, а истории негде лежать. Косинус по темам ждёт эмбеддингов.
  Такое слагаемое отключается и называет причину, а не обнуляется: обнулённое
  неотличимо в отчёте от посчитанного и давшего ноль.
- Экспорт в Sheets, чат ревьюера с моделью.

## Где что лежит

```
backend/src/avito_reviewer/
  config.py              все настройки, читаются из окружения
  ingest/                ссылка → SubmissionBundle; резолвер content_ref
  ai/
    content.py           тексты артефактов и флаг partial
    rubric.py            схема рубрики, проверка, каталог
    compiler.py          условие → черновик рубрики
    gate.py              формальные проверки без токенов
    llm/                 PrivacyGateway — единственный выход к моделям
    review/              промпт, валидатор цитат, агрегатор
    detection/           ансамбль сигналов ГенИИ
  distribution/          раскладка работ по ревьюерам, к модели ходит только profile.py
  app/                   HTTP-слой
backend/rubrics/         рубрики как данные: добавить курс = добавить JSON
backend/reviewers/       ревьюеры как данные; занятость туда не пишут
backend/scripts/fixtures/  записанные сдачи и условия для прогонов без сети
```
