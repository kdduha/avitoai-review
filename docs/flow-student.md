# Студент

Студент почти не работает в интерфейсе. Продукт устроен так, что его сдача —
это pull request в том же GitHub, где он и писал код. Всё, что нужно от
студента, происходит до нашего продукта; интерфейс нужен ему дважды: сдать
ссылку и прочитать оценку.

## Что и куда он кладёт

Единственный вход — **pull request на GitHub**. Адрес разбирается регулярным
выражением (`ingest/providers/github.py::_LINK_RE`):

```
https://github.com/<owner>/<repo>/pull/<number>
```

Другая форма ссылки — `InvalidLinkError`, недоступный PR — `ProviderFetchError`.
Ветку, форк, коммит, архив или файл продукт не принимает: в перечислении
источников (`ingest/models.py::SubmissionSource`) одно значение — `github_pr`.

Публичный репозиторий читается без токена. Приватный требует
`INGEST_GITHUB__TOKEN`; без токена анонимный лимит GitHub API — 60 запросов в
час на весь контейнер.

Никакой загрузки файлов в продукт нет и не планируется. Мы забираем из PR:

| Что забираем | Зачем |
|---|---|
| дифф по каждому файлу и номера изменённых строк | предмет разбора |
| дерево файлов на `head` | контекст: что вообще есть в репозитории |
| историю коммитов — sha, время, псевдонимный автор, ±строк | форензика: как работа собиралась |
| момент открытия PR | это и есть время сдачи, с ним сверяется срок |
| `base`/`head` sha | границы изменения |

Полные тела файлов сразу не тянутся: у артефакта есть `content_ref`, и агент
разбора дочитывает файл, только если он ему понадобился. Роль каждого файла
проставляется эвристикой — `solution`, `evidence`, `tooling`, `noise`;
лок-файлы и вывод сборки в разбор не идут.

## Что имеет значение в том, как студент готовит работу

- **История коммитов — часть предмета.** Сигнал о следах ГенИИ смотрит на то,
  как работа собиралась. Ветка, собранная одним коммитом, даёт форензике 0.80 —
  ровно это произошло с учебными PR в демо-данных (`docs/demo-data.md`), и
  сигнал там говорит о способе сборки демо, а не о работе студента.
- **Формальные требования условия проверяются по файлам PR.** Что именно
  требуется — README, лог прогона, тесты, имя ветки — записано в рубрике
  задания. Непройденное требование не останавливает разбор: гейт проверяет, но
  не запрещает.
- **Имени студента в разборе нет.** В бандл идёт `StudentRef.internal_id` —
  хеш; наружу к модели всё уходит через `PrivacyGateway`. Ревьюер видит
  внутренний идентификатор, не логин.

## Как ссылка попадает к нам

Два пути, и второй не требует от студента вообще ничего:

1. **Студент сдаёт сам.** `/my-work` → «Сдать работу» → `POST /me/submissions`
   с `assignment_id` и ссылкой. Нужен аккаунт и зачисление на поток задания.
   `403` — не зачислен, `409` — задание ещё не открыто, `404` — нет задания
   или его рубрики в каталоге.
2. **Ревьюер заводит работу руками.** `/check` → `POST /review` с той же
   ссылкой. Студенту достаточно открыть PR и сказать, где он.

Просрочка сдачу не запрещает. Штраф считает агрегатор по `late_policy` рубрики;
решение «поздно, но зачесть» принадлежит правилам курса, а не форме сдачи.

Каждая сдача — новая строка. «Сдать ещё раз» доступно всегда, дедупликации нет
(`docs/todo.md`). В карточке задания показывается лучший из **утверждённых**
баллов.

## Что студент видит в интерфейсе

Один экран — `/my-work`, стартовый для роли `student`. Ни очередь, ни рубрики,
ни каталог курсов ему не открываются: рубрика показывает устройство шкалы до
того, как работа оценена.

**К сдаче** — задания своих потоков, сгруппированные по курсу: название, срок,
максимальный балл, описание, сколько раз уже сдавал, лучший зачтённый балл.
Нет заданий — так и написано: либо не зачислен на поток, либо методист не
выдал потоку ни одной рубрики.

**Сданное** — карточка на каждую сдачу. До утверждения ревьюером в ней ссылка,
дата и строка «На проверке у ревьюера — оценка появится, когда он её
утвердит». Балла нет вовсе, и это не состояние загрузки: разбор моделью уже
посчитан, но оценку ставит человек.

После утверждения появляются:

- балл из максимума и «зачёт» / «не зачтено» с объяснением, как сложился итог,
  и отдельной строкой про просрочку, если она была;
- отзыв о работе словами — что получилось, что доработать, поддерживающая
  фраза. Собирается из уже проверенных вердиктов, исходников ему не
  показывают: соврать про код можно, только если его видишь;
- разбор по критериям — балл, объяснение, «что докрутить».

Чего в кабинете студента нет намеренно: цитат из кода, уверенности модели,
пометок «требует внимания», сигнала о следах ГенИИ. Это кухня проверки, а не
обратная связь (`app/routers/student.py`, `app/schemas/student.py`).
