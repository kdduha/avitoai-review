# Фронтенд: состояние и как его воспроизвести

Парный к `handover-backend.md`: что работает, как запустить и на чём здесь
спотыкаются.

React + Vite + TypeScript, TanStack Query, Tailwind v4, Recharts.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build
npm run typecheck
npm run gen:api    # типы из OpenAPI поднятого бэкенда
npm run e2e        # Playwright: сам поднимает и фронт, и бэкенд
```

Бэкенд нужен для проверки работ; ведомость и дашборд открываются и без него.

```bash
cd ../backend && uv run uvicorn avito_reviewer.app.main:app --port 8000
```

`/api` проксируется на `http://localhost:8000` (`vite.config.ts`),
переопределяется переменной `VITE_API_BASE`.

## Что здесь есть

| Маршрут | Экран | Данные |
|---|---|---|
| `/check` | запуск проверки по ссылке | живой API |
| `/review/:id` | Review Workspace: правка балла, вердикт по спану, утверждение, чат с моделью | живой API (демо — офлайн) |
| `/rubrics` | каталог рубрик; руководителю — сборка новой из условия | живой API |
| `/queue` | своя очередь (руководитель — весь поток, `?all=true`) | живой API |
| `/streams` | потоки: сдачи, очередь, просрочка, баллы, нагрузка; руководителю — назначение ревьюеров и раскладка | живой API |
| `/assignments` | какая рубрика выдана какому потоку и до какого числа | живой API |
| `/my-work` | кабинет студента: что сдавать, что сдано, что получено | живой API |
| `/courses/:id` | ведомость, дашборд, ревьюеры потока | синтетика |
| `/students/:id` | карточка студента | синтетика |
| `/curators` | кто на каких потоках | синтетика |

Ролей четыре, и называются они **как на сервере**: `student`, `reviewer`,
`methodist`, `admin`. Свой словарь фронта («curator» / «head») разъезжался с
сервером молча. Русские подписи живут в `RoleSwitch`.

Роль переключается в шапке и лежит в `localStorage`; при переключении
`app/session.tsx` логинится в одноимённый сеяный аккаунт (пароль
`VITE_BACKEND_PASSWORD`/`avito2026`) и держит токен в `lib/backend.ts`.
Сохранённая роль проверяется на существование: `localStorage` переживает
обновление интерфейса, и неизвестное значение откатывается к `reviewer` — иначе
вход молча не проходит и все запросы уходят без токена. Кнопка «Войти»
(`LoginModal.tsx`) пускает под аккаунтом, заведённым через `POST /users`.

`lib/types.ts::atLeast` повторяет серверную лестницу прав, но решает только,
**что показать**; что разрешить, решает сервер.

**Review Workspace — две колонки, а не три.** Слева работа, справа одно окно с
вкладками «Черновик оценки» и «Признаки ГенИИ». Панель детектора занимала треть
ширины и почти всегда была пуста. Над списком критериев закреплена ровно одна
строка — формальные проверки; отзыв, «требуют внимания» и объяснение итога живут
внутри прокрутки: три закреплённых блока подряд оставляли списку критериев одну
строку.

Чат (`ChatDock.tsx`) на живом прогоне читает историю (`GET .../chat`) и ведёт ход
через SSE (`POST .../chat`, `backend.ts:sendChat`) — сервер досчитывает весь ход
и отдаёт его как последовательность `data:`-событий, не токен за токеном. Шаг с
`tool_name` подписан («читает файл», «смотрит дифф»); шаг с `proposed_patch`
получает кнопку «Применить», которая уходит в тот же
`PATCH /submissions/{id}/review`, что и ручная правка балла. На демо-прогонах
чат read-only.

## Где что лежит

```
src/lib/backend.ts     клиент бэкенда; backend.d.ts генерируется из OpenAPI
src/lib/workspace.ts   три ответа сервера → один вид для панелей
src/lib/runs.ts        прогоны проверки: живые (с сохранением на сервере) и записанные
src/lib/api.ts         данные админки, которых у бэкенда ещё нет
src/app/session.tsx    роль → авторизация: логин в сеяный аккаунт, токен в lib/backend.ts
src/mocks/             каталог программ и записанные прогоны
src/features/review/   Review Workspace и запуск проверки
src/features/rubrics/  каталог рубрик + CompileRubricPanel (условие → черновик → подтверждение)
src/features/teaching/ потоки со статистикой и задания со сроками
src/features/student/  кабинет студента
src/features/courses/  ведомость, дашборд, ревьюеры — на синтетике
src/styles/index.css   токены визуального языка
e2e/                   Playwright: обход маршрутов, правка балла, вход, компилятор рубрик
```

## Docker

```bash
docker compose up --build frontend   # из корня — соберёт и бэкенд с базой заодно
```

Многоступенчатый билд: `npm run build` → статика в nginx (`Dockerfile`,
`nginx.conf`). `/api/*` nginx проксирует на сервис `backend:8000` — тот же путь,
что у `vite.config.ts` в dev, только имя хоста другое.

## Граница живого и синтетики

**Живое** — `GET /init`, `GET /rubrics`, `GET /rubrics/{id}`,
`POST /rubrics/compile`, `POST /rubrics`, `GET /cost`, `POST /review`,
`POST /detect`, всё под `/submissions/*` и `/me/queue`. Клиент —
`src/lib/backend.ts`; каждый запрос несёт `Authorization: Bearer <token>` из
`app/session.tsx`.

**Синтетика** — курсы, потоки, студенты, ведомость, ревьюеры на `/courses/*`,
`/curators`, `/students/*`. Вся за `src/lib/api.ts`, форма функций — та, что
появится в REST.

Правка балла (`PATCH /submissions/{id}/review`), вердикт по спану
(`POST /submissions/{id}/ai-detection/{span_id}/verdict`) и утверждение уходят на
сервер и возвращают то, что он посчитал и сохранил — `setScore` /
`setSpanVerdict` в `lib/runs.ts` асинхронны поэтому. `submissionId === null`
(демо-прогоны из `mocks/`) — сигнал, что PATCH'ить нечего, и правка остаётся
локальной прикидкой с пометкой `edited`.

Открытие сдачи не из этой вкладки (по ссылке `/review/{id}` или из очереди) идёт
через `GET /submissions/{id}` (`lib/runs.ts:loadSubmission` →
`lib/workspace.ts:buildWorkspaceFromDetail`) — используется снимок рубрики из
ответа (`SubmissionDetail.rubric`), а не текущий каталог: правка JSON методистом
не должна молча пересчитывать старые сдачи.

`src/mocks/` импортируют ровно два файла: `lib/api.ts` (каталог) и `lib/runs.ts`
(записанные прогоны). Компоненты ходят только через запросы. **Импорт чего-либо
из `mocks/` в компонент — сигнал, что абстракция протекла**; такая протечка уже
стоила отдельного рефакторинга.

Мок-экраны помечены плашкой `MockNotice`.

## Данные

### Программы

`src/mocks/programs.ts` — каталог по материалам организаторов (репозиторий
`ai-talent-hub-avito/homework_examples`). Из девяти направлений оставлены пять —
те, у которых есть записанный разбор: открыть курс и не суметь провалиться
внутрь задания хуже, чем не показать курс вовсе. Они же покрывают разнообразие:
шесть каналов сдачи, три шкалы (6, 10 и 20 баллов), от одного задания до трёх.

Что взято из условий и легко потерять при правках:

- **шкалы разные**, и на Go баллов в условии нет вовсе — их задаёт методист;
  распределения на дашборде считаются в долях от максимума;
- **досдача** в grace-окно стоит балл за день, позже работа оценивается в ноль;
- **проверка идёт волной**: «начинается после окончания дедлайна и занимает не
  более 7 дней» — отсюда всплеск на графике по неделям;
- **строка ведомости** повторяет таблицу организаторов: сумма за ДЗ,
  посещаемость, вовлечённость, экзамен, итог и оценка, где
  `итог = сумма × 0.5 + экзамен × 0.4 + вовлечённость / 10`;
- **идентификаторы студентов** обезличены шестизначным числом.

Данные детерминированы: два открытия страницы дают одну и ту же ведомость.

### Записанные прогоны

Лежат **в формате ответов бэкенда** (`ReviewResponse` / `DetectResponse`) и
проходят через тот же адаптер `lib/workspace.ts`, что живой прогон: своя форма у
демо означала бы, что расхождение с сервером всплывёт только на живом ключе.
Состав и происхождение — в [demo-data.md](demo-data.md).

Разбор доступен там, где есть рубрика. Показывать разбор работы по Tech QA
против рубрики по Go хуже, чем не показывать ничего.

## Грабли: что диктует бэкенд

- **название, максимум, вес и проверочные пункты критерия лежат в рубрике** —
  вердикт знает только `criterion_id`. Панель соединяет их сама;
- **`line_numbers`, а не `first_line + index`.** У фрагмента из диффа номера
  строк идут с пропусками (1–4, затем 119–122). Нумерация по позиции уводит
  цитату на чужую строку — на `partial`-файлах это выглядит правдоподобно;
- **`partial`** значит, что модель видела не весь файл, и вывод «этого в работе
  нет» здесь ненадёжен;
- **у проверки Format Gate есть третье состояние** — `inconclusive`: ответить по
  доступным данным нельзя. Это не провал;
- **гейт не останавливает разбор.** Статуса `blocked` нет: непройденная проверка
  уровня `blocking` выводится заметной строкой, но модель отрабатывает;
- **недоступный сигнал детектора — не ноль, а «не смотрели»**;
- **итог считает агрегатор**: веса, шаг шкалы, обязательные минимумы и штраф за
  просрочку, причём два последних могут обнулить работу целиком. Предварительная
  сумма по критериям (`edited`, без пересчёта) осталась только на демо-прогонах.

Типы генерируются из OpenAPI (`npm run gen:api`), руками `backend.d.ts` не
правят. Так и обнаружилось появление `student_name` в API.

**nginx во `frontend`-контейнере по умолчанию рвёт `/review` на реальном ключе.**
Дефолтный `proxy_read_timeout` — 60s; настоящий разбор с несколькими батчами
критериев и детектором занимает больше (зафиксировано 4 минуты 9 секунд на
реальном PR). Без ключа этого не видно. `frontend/nginx.conf` держит
`proxy_read_timeout 300s` (и `send`/`connect` тоже) — не трогайте вниз.

## Как добавить

**Программу в каталог** — запись в `PROGRAMS` (`src/mocks/programs.ts`).
Ведомость, дашборд, потоки и студенты соберутся сами.

**Рубрику** — JSON в `backend/rubrics/`. Каталог и экран `/rubrics` подхватят её
без правок фронта. Сумма максимумов критериев должна сходиться с
`scale.total_max`.

**Записанный прогон** — файл рядом с `src/mocks/demoBackend.ts`: снимок рубрики в
`src/mocks/rubric.ts`, файлы работы, черновик и отчёт детектора в формате ответов
бэкенда. Зарегистрировать в `src/lib/runs.ts`, добавить в `DEMO_BY_COURSE` и
`DEMO_BY_RUBRIC`. Цитаты не проставляют руками — их ищет `locator()` по тексту
файла, как это делает настоящий валидатор.

## Что не сделано

1. **`/courses/*`, `/curators`, `/students/*` остаются синтетикой.** Сущности на
   бэкенде есть, и статистика по ним считается по-настоящему на `/streams`.
   Перевести старый дашборд значит потянуть за собой студентов, ведомость и
   формулу итога — отдельный заход.
2. **Идентификаторы в коде отстают от словаря.** `Curator`, `curatorId`, маршрут
   `/curators` — пользователю не видны, но расходятся с сервером, где `reviewer`.
3. **Управления аккаунтами нет.** Заводить людей и менять роли — через
   API/Swagger; `LoginModal` умеет только вход.
4. **Кабинет студента — только свои работы.** Истории попыток по одному заданию,
   дедлайнов календарём и уведомлений нет.
5. **Экрана распределения нет.** `POST /distribute` на бэкенде раскладывает пакет
   сдач и объясняет каждое назначение; во фронте раскладка доступна только
   кнопкой на `/streams`.
6. **Playwright покрывает** вход, обход маршрутов, правку балла, переход по
   цитате и сборку рубрики. Потоки, задания и кабинет студента появились позже и
   не покрыты.

## Визуальный язык

Метафора — не терминал, а разметка на полях: ревьюер читает работу и оставляет
пометки. Бумага `#fbfbfa` на поле `#f1f2f0`, графитовый текст, единственный
интерактивный цвет — чернильно-синий, подсветка цитаты — песочная полоса с
линейкой слева. Моноширинный шрифт только там, где код или путь.

Одно громкое место на экран: в Review Workspace это итоговый балл, и кнопка
утверждения стоит рядом с числом, которое утверждает. Токены —
`src/styles/index.css`, палитра графиков проверена на различимость при
дальтонизме.
