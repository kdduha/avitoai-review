# Frontend

Рабочее место куратора: React + Vite + TypeScript, TanStack Query, Tailwind v4, Recharts.

```bash
npm install
npm run dev        # http://localhost:5173
npm run gen:api    # типы из OpenAPI поднятого бэкенда
npm run build
```

`/api` проксируется на `http://localhost:8000` (`vite.config.ts`); переопределяется
переменной `VITE_API_BASE`.

## Что живое, а что ещё нет

Бэкенд без состояния: он принимает ссылку на сдачу и отдаёт разбор, но нигде его
не хранит. Отсюда деление.

| Экран | Данные |
|---|---|
| `/check` — запуск проверки | `GET /init`, `GET /rubrics`, `GET /cost`, `POST /review`, `POST /detect` |
| `/rubrics` — против чего оценивают | `GET /rubrics`, `GET /rubrics/{id}` |
| `/review/:runId` — Review Workspace | результат прогона, живёт в памяти вкладки |
| `/review/demo`, `/review/demo-sysdesign`, `/review/demo-backend` | записанные прогоны в формате ответов бэкенда |
| `/queue`, `/courses/:id`, `/students/:id`, `/curators` | синтетика: у бэкенда нет ни каталога курсов, ни ведомости |

Мок-экраны помечены в интерфейсе плашкой — на демо должно быть видно, где работает
настоящий разбор, а где нарисованы данные.

Демо-прогон намеренно лежит в формате `ReviewResponse` / `DetectResponse`
(`src/mocks/demoRun.ts`): живой и демонстрационный путь проходят через один
адаптер `src/lib/workspace.ts` и рисуются одним кодом, поэтому расхождение с
сервером нельзя не заметить.

## Синтетические данные

Каталог программ в `src/mocks/programs.ts` собран по материалам организаторов
(репозиторий `ai-talent-hub-avito/homework_examples`), а не выдуман. Из девяти
направлений оставлены пять — подобранные на разнообразие, а не на полноту: три
канала сдачи, три шкалы (6, 10 и 20 баллов), от одного задания до пяти.

У трёх программ есть рубрика в `backend/rubrics/`, и для каждой записан свой
разбор:

| Прогон | Работа | Чем отличается |
|---|---|---|
| `demo` | сервис на Go, pull request | шкала 10, провал формального требования |
| `demo-sysdesign` | Markdown с диаграммой C4 | шкала 6 с дробными критериями, работа ровно на пороге, две проверки гейта без ответа |
| `demo-backend` | FastAPI и тесты | промежуточная градация 0.5 из условия, штраф за просрочку уводит зачёт ниже порога |

У двух программ рубрики нет — ячейка ведомости там не ссылка. Показывать разбор
работы по Tech QA против рубрики по Go хуже, чем не показывать ничего.

Что из этого важно для интерфейса и легко потерять при доработках:

- **шкалы разные** — 10 баллов у большинства, 6 у первой лабы системного
  дизайна, 20 у Tech QA. Распределения на дашборде строятся по доле от
  максимума, иначе столбцы сравнивают несравнимое;
- **баллов в условии может не быть вовсе** — на Go шкалу задаёт методист;
- **правило досдачи из условий**: один день после дедлайна стоит балл, позже
  работа оценивается в ноль. Генератор оценок это воспроизводит;
- **проверка идёт волной**, а не потоком: «начинается после окончания дедлайна
  и занимает не более 7 дней». Отсюда всплеск на графике по неделям;
- **строка ведомости** повторяет таблицу организаторов: сумма за ДЗ,
  посещаемость, вовлечённость, экзамен, итог и оценка, где
  `итог = сумма × 0.5 + экзамен × 0.4 + вовлечённость / 10`;
- **идентификаторы студентов обезличены** шестизначным числом — так же, как в
  настоящей ведомости.

Данные детерминированы: два открытия страницы дают одну и ту же ведомость.

## Типы

`src/lib/backend.d.ts` сгенерирован из `/openapi.json` — руками его не правят.
`src/lib/backend.ts` даёт клиент и именованные типы поверх него. Своё в
`src/lib/types.ts` осталось только для сущностей, которых у бэкенда пока нет
(курсы, потоки, ведомость, кураторы).

Что бэкенд диктует интерфейсу, и это важно не потерять при доработках:

- название и максимум критерия лежат в рубрике, а не в вердикте — панель
  соединяет их сама;
- текст файла может начинаться не с первой строки (`first_line`) и быть
  фрагментом (`partial`) — нумерация и предупреждение в панели работы отсюда;
- Format Gate возвращает разбор проверок; при `blocked` модель не запускалась,
  и черновик надо читать иначе;
- недоступный сигнал детектора — не ноль, а «не смотрели»: панель показывает
  статус каждого сигнала и его вес;
- название, максимум, вес и проверочные пункты критерия лежат в рубрике —
  вердикт знает только `criterion_id`;
- итог считает агрегатор: веса, шаг шкалы, обязательные минимумы и штраф за
  просрочку. Правка балла куратором показывает сумму как предварительную и не
  выносит вердикт о зачёте, пока нет `PATCH /review`.

## Визуальный язык

Метафора — не терминал, а разметка на полях: куратор читает работу и оставляет
пометки. Бумага `#fbfbfa` на поле `#f1f2f0`, графитовый текст, единственный
интерактивный цвет — чернильно-синий, подсветка цитаты — песочная полоса с
линейкой слева. Моноширинный шрифт только там, где действительно код или путь.

Одно громкое место на экран: в Review Workspace это итоговый балл. Токены —
`src/styles/index.css`, палитра графиков проверена на различимость при
дальтонизме.
