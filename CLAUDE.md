# Как работать в этом репозитории

Файл для того, кто берёт проект дальше, и для его агентов. Не пересказ
архитектуры — она в `docs/`. Здесь то, что экономит день: правила, которые
здесь уже оплачены ошибками.

Начинать с `docs/handover-backend.md` и `docs/handover-frontend.md` — только
они обещают отражать код как он есть. `docs/architecture.md` описывает целевую
форму, и расходится с кодом намеренно.

---

## Запуск

```bash
docker compose up --build          # postgres, redis, backend, worker, frontend
```

UI — http://localhost:5173, API — http://localhost:8000, Swagger — `/docs`.

Без ключей поднимается провайдер `fake`: весь путь проходится, модель молчит,
вердикты приезжают пустыми. Это штатный режим, а не поломка. С ключом:

```bash
AI_LLM__PROVIDER=external AI_LLM__API_KEY="$ключ" \
INGEST_GITHUB__TOKEN="$(gh auth token)" docker compose up -d backend worker
```

Токен GitHub нужен, только если разбираемые PR лежат в приватном репозитории —
публичные ingest берёт и без него.

Сеяные аккаунты: `student`, `reviewer`, `methodist`, `admin`, пароль
`avito2026` (`AUTH_SEED_PASSWORD`). Под каждую карточку из `backend/reviewers/`
на старте заводится свой аккаунт с логином, равным имени файла.

Проверки, которые обязаны быть зелёными перед коммитом:

```bash
cd backend  && uv run ruff check src tests && uv run mypy src && uv run pytest
cd frontend && npm run typecheck && npm test && npm run check:runs
```

## Правила, нарушение которых уже стоило времени

**Сверяйтесь с `origin/main` до начала работы.** Ветки здесь двигаются из
нескольких сессий сразу. В этом репозитории уже был случай, когда фича
делалась второй раз: `with_detection` строился заново, хотя лежал в `main`.
`git fetch origin && git log --oneline main..origin/main` — тридцать секунд.

**Не работайте в чужом дереве.** Если рабочее дерево грязное, это чья-то
незакоммиченная работа. Заводите своё: `git worktree add --detach <путь>
origin/main`. Особенно это касается агентов — трое подряд однажды принесли
отчёт «чата нет, БД нет, auth нет», потому что читали устаревшую ветку. Давайте
агенту путь свежего worktree и явный запрет читать рабочий каталог.

**Типы фронта генерируются, а не пишутся.** `frontend/src/lib/backend.d.ts` —
вывод `npm run gen:api` из OpenAPI поднятого бэкенда. Правка руками разъедется
с сервером молча. Если бэкенд не поднят, поднимите временный на SQLite:

```bash
cd backend && DB_DSN="sqlite+aiosqlite:////tmp/gen.db" AUTH_JWT_SECRET=dev \
  uv run uvicorn avito_reviewer.app.main:app --port 8079 &
cd frontend && npx openapi-typescript http://127.0.0.1:8079/openapi.json -o src/lib/backend.d.ts
```

**Миграции пишутся под оба диалекта.** Тесты гоняют alembic на SQLite,
docker-compose — на Postgres. Автоген выдаёт безымянные внешние ключи, которых
SQLite не умеет; оборачивайте такие правки в `op.batch_alter_table` и задавайте
имена явно.

**Даты из базы приводите к осведомлённым.** Колонки объявлены
`DateTime(timezone=True)`, но SQLite зону не хранит и отдаёт наивное время, а
Postgres — осведомлённое. Сравнение падает `TypeError` то в тестах, то в проде,
смотря где повезёт. Ловили дважды.

**Ленивые связи в async-сессии не трогайте.** `assignment.stream` поднимает
`MissingGreenlet`; берите `await session.get(...)`.

**Правьте зеркало серверной валидации рубрик.** `frontend/src/lib/rubric.ts`
дословно повторяет `backend/.../ai/rubric.py::validate_rubric`, и есть тест,
который ловит расхождение. Меняете правило на сервере — правьте зеркало.

## Решения, которые не надо пересматривать наугад

У каждого есть цена, заплаченная за то, чтобы понять, почему иначе нельзя.

**Балл считает код, а не модель.** Модель отвечает по одному критерию и обязана
приложить цитату; цитата сверяется с текстом файла программно, сумму считает
агрегатор. Промпт прямо запрещает модели складывать.

**Гейт проверяет, но не запрещает.** Непройденное дословное требование — повод
рассказать, а не остановить разбор. Раньше оно возвращало работу ревьюеру, не
запуская модель, и студент за одну недостающую строку в логе не получал ни
слова о том, что сделано хорошо. Статуса `blocked` больше нет.

**Отзыв о работе не видит файлов.** `ReviewSummary` собирается из уже
проверенных вердиктов; исходников ему не показывают. Соврать про код можно,
только если его видишь.

**Студенту не показывают черновик.** До утверждения ревьюером у работы нет ни
балла, ни отзыва — «на проверке». Показать предварительное число значило бы
объявить студенту решение, которое приняла модель.

**Чужая сдача — 404, а не 403.** Существование чужой работы тоже сведение о ней.

**Срок принадлежит заданию, а не сдаче.** `POST /review` с `assignment_id`
берёт рубрику и дедлайн из задания и **игнорирует** `deadline_at` из тела:
иначе поле остаётся местом для опечатки, которая даёт необъяснимый штраф.

**Рубрика замораживается снимком.** `Submission.rubric_snapshot` — та рубрика,
против которой ставили балл. Правка файла задним числом не меняет уже
выставленные оценки.

**Чего нет в материалах — того нет в коде.** Нет порога зачёта в условии —
`pass_threshold: null`, а не «60% от максимума». Нет шкалы — не выдумывать.
Отсутствие данных подписывается словами, а не заполняется правдоподобным.

**Пустое место честнее заглушки.** Не собралось резюме — `None`. Нет
утверждённых работ — `average_score: null`, а не ноль: ноль читается как «все
написали на ноль».

## Что стоит сделать следующим

По убыванию пользы, подробности в `handover-*`.

1. **Учёт расхода по людям.** Всё для этого есть, кроме двух полей: у
   `AuditRecord` нет `user_id` и `submission_id`, и журнал живёт в памяти
   процесса. Дешёвый первый шаг — помечать применённый из чата патч как
   `AuthorType.AI_ASSISTED`: значение объявлено и не используется ни разу, а по
   нему считалось бы «работ проверено с помощью ИИ».
2. **Перплексия как сигнал.** `LogprobScorer` объявлен и нигде не
   конструируется — `AI_LLM__PROVIDER=local` её не включит. Ансамбль сегодня
   три сигнала из четырёх.
3. **Старый дашборд курса на реальные данные.** `/streams` уже считает по
   `submissions`; `/courses/:id` всё ещё на `mocks/catalog.ts`.
4. **Подстановка чужого демо-прогона.** `demoRunForRubric` возвращает разбор по
   Go для любой рубрики без записанного прогона. Исправление лежит в ветке
   `frontend-wip-rescue`.
5. **Дедупликация сдач.** `POST /review` создаёт новую строку на каждый вызов.

## Демонстрационные данные

`backend/scripts/seed_demo_submission.py` заводит показательную сдачу с
зачётом: черновик собирается настоящим конвейером на записанных ответах
модели, цитаты берутся из настоящих строк файлов. Готовый черновик, вписанный
в базу, разошёлся бы с кодом при первой правке рубрики.

В репозитории лежат учебные PR с решениями студентов из публичного
репозитория организаторов — по одному на задание, против пустой ветки
`demo/base`, чтобы в дифф попадала только сдача. Они не вливаются.

Полный состав демо-данных, откуда что взято и **чему верить не стоит** —
[docs/demo-data.md](docs/demo-data.md). Коротко: разбор по критериям на этих PR
настоящий, а сигнал ГенИИ — нет. У всех семи он равен `0.40`, потому что
форензика истории даёт 0.80 каждой: каждая ветка собрана одним коммитом, и
правило срабатывает на способ сборки демо, а не на работу студента.
